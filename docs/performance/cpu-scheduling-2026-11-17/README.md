# CPU 调度优化与验证 — 2026-11-17

本次修改减少小工作量门的任务创建，限制批量外层任务数，并在同一 CPU 分区中串行执行嵌套任务。**已观察到明确的小态/CNOT 收益；本报告不声称所有规模都加速。** 20 比特整条线路在主要配对实验中反而慢约 7.4%，25 比特接近持平。

## 主要结果：同进程、同一状态缓冲区

主比较同时加载优化前后的两个 MOSS 模块，让它们使用同一个 `Vector{ComplexF64}`。每次执行前在计时外重置状态，交替先后顺序；每条路径预热后各测七次。每个正式样本结束后，都在计时外与旧模块产生的完整参考态比较。共享缓冲区减少两个独立状态可能带来的物理页/NUMA 放置差异，不能消除全部系统噪声。

下表使用七次耗时的中位数，单位秒；倍率为旧耗时/新耗时，超过 1 表示变快。数据来自 [paired-shared-16.toml](paired-shared-16.toml)，16 个 Julia 线程：

| 线路 | 旧实现 | 新实现 | 旧/新 |
| --- | ---: | ---: | ---: |
| 15 比特，深度 20，完整公开调用 | 0.024488401 | 0.016065714 | 1.5243× |
| 15 比特，深度 20，仅 CNOT 直核 | 0.011264658 | 0.002472879 | 4.5553× |
| 20 比特，深度 20，完整公开调用 | 0.241195702 | 0.259054665 | 0.9311× |
| 25 比特，深度 10，完整公开调用 | 4.787972863 | 4.696637564 | 1.0194× |

15 比特整条线路的七对样本均变快，逐对旧/新为 1.436–1.725；CNOT 组为 4.290–5.531，七对也全部变快。20 比特七对中有五对变慢，旧范围为 0.220079–0.255946 秒，新范围为 0.221772–0.296436 秒；保留这一回退，不将其解释为加速。25 比特逐对倍率为 0.753–1.304，样本波动远大于中位数约 2% 的差距，宜表述为接近持平。这些范围不是置信区间。

另有 [两个独立状态的配对实验](paired-16.toml)。相同四行的倍率分别为 1.5063×、4.8678×、0.9841×、0.8740×。25 比特的结论对缓冲区方案和测量窗口敏感，因此该实验单独归档，不与共享状态结果拼接，也不能仅凭此确定 NUMA 是原因。两套配对数据均完整保留于 [paired.csv](paired.csv)；该表区分“中位耗时之比”和“逐对倍率的中位数”。

## 修改范围

生产改动仅涉及七个 CPU 文件，完整前后源码见 [before/source](before/source)、[candidate/source](candidate/source) 和 [after/source](after/source)。不改变门的数值公式、量子比特位序、精度提升或返回状态规则。

- `parallel_run` 按可用线程、调用预算和最低工作量限制实际任务数；单任务直接在调用者执行。并行路径仍在所有分区结束后返回，工作任务异常也等待其余任务完成再传播。
- 分区使用 task-local 标记，嵌套 `parallel_run` 在当前 task 内执行，避免批量外层与单态内层同时扩展任务。
- 最终候选的最低工作量为 dense 单比特核 256、swap/X/CNOT 16384、phase/CZ/CPHASE 32768 个调度迭代。每次迭代的工作量随门核不同，不能将这些数字解释为相同的振幅数量。
- 纯态批量与密度矩阵批量共用受限列调度；小批量保留状态内部并行，较大批量按总工作量限制外层任务数。gate、channel 与 dagger 保留原校验及精度规则。

`parallel_sum` 与其他直接使用 `Threads.@threads` 的入口没有改动。RZ 对角专用核没有作为本次生产修改引入；本文不把此前诊断消融当作当前调度收益。phase/CZ 和批量路径通过功能测试，但本报告没有它们的专属吞吐对比。

## 校准、顺序测量与证据范围

全部主要测量为本轮同机重新采集，没有复用 11 月 16 日的耗时。记录版本为 Julia 1.13.3、MOSSQuantum 0.1.2、ComplexF64、BLAS 单线程。允许使用的 16 个逻辑 CPU 为 `10,68,71,79,84,86,90,123-125,127,131,135,148,180,188`；各记录及每组前后资源检查一致。

[before](before)、[candidate](candidate) 和 [after](after) 保留三个独立顺序测量阶段。15/20 比特深度 20 使用 1/8/16 线程，最终阶段补测 2/4 线程，每组五次；25 比特深度 10 使用 16 线程，每组三次。每个配置分别测完整公开调用、跳过公开入口的直核循环、旋转子线路与 CNOT 子线路，并记录全部耗时、分配和 GC。总共 100 组、476 个样本。

初始 `candidate` 使用较保守的粒度，最终 `after` 的粒度结合 [task-sweep.toml](task-sweep.toml) 调整。该扫描有 26 组、130 个样本，通过诊断覆盖固定实际任务数量；它不是另一个生产 API，也不证明每种硬件的最佳任务数。原始辅助诊断 [before/moss-16.toml](before/moss-16.toml) 的 84 个样本另计，不混入校准或配对倍率。

顺序阶段的大态结果存在明显波动。例如 25 比特最终公开调用为 3.926–5.226 秒，CNOT 子线路为 1.559–2.287 秒；同线程顺序阶段的旧/新整线路倍率只有约 0.856，无法据此宣称整体加速。15 比特的小 CNOT 任务开销改善在顺序阶段和两套配对中方向一致，是更可靠的观察。

计时包含调用内的门准备、任务创建及数值执行；重置、显式 GC、状态分配、参考写入/读回与数值检查在计时外。公开接口与直核循环不是完全等价的调用路径，不能把两个独立中位数之差当作精确的准备成本。旋转和 CNOT 子线路各自从零态执行，耗时也不能直接相加作为完整线路的分解。七对实验交替先后顺序，首执行次数为 4:3，未进行随机化或置信区间估计。

## 正确性、来源与测试

旧生产模块先写出 CPU 参考二进制及元数据。后续候选/最终输出读取相同旧参考，不用新代码重新生成 oracle。不同线程使用独立 baseline 目录，已有参考只允许校验一致，不覆盖。元数据保存角度、完整字节数、SHA-256、建立线程数和旧核心源码指纹；二进制保留在服务器，仓库只保留 [baseline-1](baseline-1)、[baseline-8](baseline-8) 和 [baseline-16](baseline-16) 元数据。

校准记录共保存 50 份公开调用/直核的逐振幅校验结果，幅度数与 15/20/25 比特完整状态相符，最大相对 L2 和最大振幅差均为 **0**。`write` 阶段建立并往返校验旧参考，`check` 阶段校验候选/最终实现；分组只检查范数。两套配对各四个配置的 L2 也为 **0**，共享状态配对会检查每次正式执行后的完整输出。

汇总器验证三阶段各 114 个核心源码摘要、同阶段版本一致、七个生产文件的变化范围、三个共同测量驱动摘要、旧参考元数据摘要及样本统计。配对和任务扫描的原始 TOML 不自带每次运行的核心摘要；它们的来源由冻结源码快照和 [benchmark-source](benchmark-source) 中的实际驱动保留，不声称原始文件包含其没有记录的字段。

## 汇总与复现

[summarize.py](summarize.py) 仅依赖 Python 标准库，重算中位数、范围和倍率，验证完整状态、源码、资源与旧参考链。输出 [summary.json](summary.json)、[顺序校准 CSV](summary.csv)、[配对 CSV](paired.csv) 与 [任务扫描 CSV](task-sweep.csv)。

```bash
python3 summarize.py --self-test
python3 summarize.py
```

测量驱动均在 `benchmark-source/`。`cpu_schedule_calibration.jl` 的参数为 `OUTPUT.toml BASELINE_DIR write|check [QUBITS] [DEPTHS] [REPS]`。先在旧源码下执行 `write`，再在候选/最终源码下用相同 baseline 执行 `check`；例如 `15,20 20 5`。重测应使用新的输出目录。共享状态配对驱动同时加载旧源码和当前包，其第二个参数是旧 `source` 目录。

结论限于本机、双精度纯态及已记录工作负载。未重测 30 比特，也未重新比较 MindQuantum、GPU、梯度吞吐或其他硬件，未证明普遍加速；20 比特观察到的回退与大态噪声均保留在主结果中。
