# 命名参数与数值参数混合设计

日期：2026-10-30。状态：已实现并完成验收；Julia 1.10、Julia 1.13 与关联包回归均通过。本页扩展[现有参数设计](parameter-design.md)，现行接口和验证记录仍见[参数指南](parameters.md)。

保留 `Parameter`、`rand()` 数值角度和 `rand(); isparas=true` 三种写法。含命名参数的线路在编译时自动给数值活动槽分配匿名参数，统一参数顺序、绑定和梯度回传。用户正常构造线路和目标时不需要手工调用 `parameterize`。

## 用户用法

以下接口支持三种参数声明在同一线路中混用。

```julia
θ = Parameter(:θ)
circuit = QCircuit([
    RxGate(1, rand(); isparas=true), # 匿名可训练角度，保留这次 rand 的结果
    RyGate(2, θ),                   # 命名可训练变量
    RzGate(1, rand()),              # 普通数值门，按原构造规则固定
    CPHASEGate(1, 2, 2θ + 0.1),     # 与第二个门共享 θ
])

H = QubitsTerm(1 => "Z") + QubitsTerm(2 => "Z")
objective = ExpectationObjective(circuit, H, StateVector(2))

x0 = initial_parameters(objective; values=Dict(θ => 0.3))
value, gradient = value_and_gradient(AdjointGradient(), objective, x0)
```

目标构造会自动编译。默认输入顺序是 `[匿名参数, θ]`，`x0` 为 `[Rx 构造时的随机数, 0.3]`。第三个门的随机角度属于固定数值，不进入训练向量；第四个门不再增加一个独立变量。

三种数值含义必须分清：

| 用户写法 | 编译规则 | 初值 |
| --- | --- | --- |
| `RxGate(1, θ)`、`RxGate(1, 2θ+φ)` | 沿用显式参数身份和表达式 | 命名变量由调用者提供 |
| `RxGate(1, rand(); isparas=true)` | 每个数值活动槽成为独立匿名输入 | 捕获门中已经保存的数值 |
| `RxGate(1, rand())` | 沿用该门当前的数值激活规则；本例为固定角度 | 数值保存在门中，不进入训练向量 |

编译读取活动槽，不根据是否调用过 `rand()` 推断可训练性，也不改变各门已有的 `isparas` 默认值。

## 编译上下文与身份

复用现有 `compile_parameters`。返回值继续保留 `.template` 和 `.parameter_map`，不增加用户必须创建的新包装类型。

```julia
compiled = compile_parameters(circuit)
parameter_order(compiled)       # [匿名句柄, θ]
parameter_info(compiled)        # 来源、初值和出现位置
bound = bind_parameters(compiled, x0)
objective = ExpectationObjective(compiled, H, StateVector(2))
```

目标、有限 shots 目标、执行计划和估计计划既接受原始线路，也接受编译上下文。原始线路会自动编译一次；传入已有上下文时复用参数身份、顺序和初值资料。

匿名身份由首次编译的快照拥有。每个活动槽的每次出现位置分配一个新的 `Parameter`，不增加另一套参数类型。分配使用独立的身份随机源，不推进模拟 RNG。绑定、求导、参数查询以及复制完整上下文均不得重新生成身份。

如果同一个数值门对象在原线路中出现两次，这两个出现位置仍是两个独立匿名参数，保留旧式独立绑定语义。相同初值也不表示共享。复用显式 `Parameter` 才表示命名共享。

分别编译同一份原始线路可以产生不同匿名身份，但输入顺序、初值和数值结果一致。长期保存匿名句柄时，必须复用对应的编译上下文或目标；不同上下文的匿名句柄不互通。

匿名身份、默认初值及来源资料保存在编译映射的参数登记表中。数值叶节点可以保持原类型，现有 `_flat_bind` 负责按出现位置写入；不必把所有数值门强制改成符号包装。单独丢弃 map 后重编译 `compiled.template`，视为一次新编译，不承诺恢复之前的匿名身份和默认资料。

## 参数登记表与查询

新增 `parameter_info`，返回独立资料快照。每个逻辑变量至少包含：

| 字段 | 含义 |
| --- | --- |
| `parameter` | 句柄；命名及混合编译为 `Parameter`，旧整数映射仍可为整数 ID |
| `kind` | `:named` 或 `:anonymous` |
| `label` | 供显示的名称或自动标签 |
| `initial` | 可用初值；没有初值时明确标为缺失 |
| `sources` | 首次编译时的指令路径、物理参数槽标识和当时的活动序号；共享变量可能对应多个位置 |
| `fixed` | 当前是否已固定及其固定值 |
| `input_index` | 当前训练向量位置；固定变量没有输入位置 |

自动标签只用于显示，不能按名字猜测或重新取得匿名身份。字典中的名称键只解析显式命名变量；匿名变量按查询返回的句柄访问。用户自定义名称即使与自动标签相同，也不会被自动共享。

来源坐标与当前写入位置分开保存。固定前面的槽之后，后续槽的活动序号会变化，不能用旧 `sources` 序号直接定位写入；需要依据稳定的物理槽标识重建当前活动行。

为此增加可选布局协议 `parameter_slots(instruction)`，返回当前活动参数对应的稳定局部槽标识。例如内置多参数门可以返回 `(1,3,5)`；编译布局同时记录指令类型、量子比特位置和这些槽标识。内置门使用自身活动掩码；外部指令在全部数值参数均活动时可采用顺序默认值，部分活动且无法推导时需声明该协议。原纯数值路径不强制新增协议。

旧的“类型、位置、活动槽数”签名不足以验证混合映射：掩码从 `[true,false]` 变成 `[false,true]` 时，槽数没变但含义已经改变，必须检测并要求重编译。

`independent_parameters(compiled)` 返回登记表中的全部独立变量，包含已经通过 `fixed` 固定的变量。`trainable_parameters(compiled)` 和 `parameter_order(compiled)` 返回当前训练输入，并采用完全相同的顺序。目标和计划提供相同查询。

原始混合线路的查询不得临时生成匿名身份。对它调用要求完整输入身份的 `parameter_order` 或 `independent_parameters` 时，应提示从编译结果或目标查询。`nparameters(circuit)` 仍可计算活动门槽数，`parameter_expressions` 仍可读取显式表达式。

## 默认顺序与显式顺序

默认按现有实际绑定顺序遍历：线路从前向后，嵌套线路递归，条件固定 then 在 else 前，门内按局部活动槽顺序。

遇到匿名槽就加入一个新输入；遇到显式参数则只在该身份首次出现时加入。两类输入交错排列，不另设“命名区”和“匿名区”。控制流运行时选择哪个分支，不能改变输入维度或顺序。

显式排序必须列出全部独立句柄，不能只指定命名变量后猜测匿名位置。混合线路需要自定义顺序时，先显式编译，再在完整上下文上重排：

```julia
compiled = compile_parameters(circuit)
a = parameter_order(compiled)[1]
reordered = compile_parameters(compiled; parameter_order=[θ, a])
```

原始混合线路直接提供命名变量列表作为 `parameter_order` 应明确拒绝，并提示上述路径。纯命名线路原有的显式排序接口保持不变。

冻结后沿完整顺序过滤掉固定变量，保留其余变量的相对顺序。对已经编译的上下文重排时，完整变量集合由 `independent_parameters(compiled)` 给出。

## 初值补全

新增初始化入口：

```julia
x0 = initial_parameters(objective; values=Dict(θ => 0.3))
```

它返回与当前 `parameter_order` 一致的完整有限实数向量：匿名变量默认使用捕获初值；命名变量由 `values` 提供。调用者也可以用匿名句柄覆盖对应初值。

未提供的命名初值必须报错，不能擅自填零、NaN 或随机数。编译和初始化不得重新抽样。无有效初值的匿名槽也必须由调用者补值；普通完整绑定仍可按既有数值写入协议覆盖原活动槽的占位值。

未知键、歧义名称、非有限值及向已经固定的变量提供训练初值均应拒绝。字典键仍遵循统一规则：全部使用参数句柄，或全部使用唯一的显式名称，不混用两种键形式。

`initial_parameters` 只构造初值，不保存训练中的当前值。优化器更新 x 后，后续求值和梯度直接使用 x，不再读取匿名默认值。所有变量固定时返回空向量。

纯数值旧线路也可使用该辅助函数。若整数 `ParameterMap` 显式共享多个槽，只有这些槽初值精确相等时才可推导一个默认输入；初值冲突时列出来源并要求按整数 ID 显式赋值，不能任选第一个或最后一个。

## 绑定与固定变量

数值向量始终代表完整的当前训练输入，梯度长度始终与向量长度相同。`evaluate`、梯度方法和 `run_sweep` 不增加隐式初值补全；参数扫描矩阵的行顺序仍由 `parameter_order` 决定。

完整字典绑定同样要求提供全部当前训练输入。匿名参数使用上下文中的句柄：

```julia
compiled = compile_parameters(circuit)
a = parameter_order(compiled)[1]
bound = bind_parameters(compiled, Dict(a => 0.2, θ => 0.3))
```

只想提供命名初值时，应显式先调用 `initial_parameters`，再绑定或训练，避免每次绑定时恢复匿名参数的初值。

`fixed` 同时接受命名句柄和匿名句柄：

```julia
compiled = compile_parameters(circuit)
a = parameter_order(compiled)[1]
frozen = compile_parameters(compiled; fixed=Dict(a => 0.2))
objective = ExpectationObjective(frozen, H, StateVector(2))
x0 = initial_parameters(objective; values=Dict(θ => 0.3)) # [0.3]
```

在已有编译上下文上允许追加固定变量，保持其余身份和初值资料；既有固定值已经代入模板，修改或解除旧固定配置仍需从原始线路重建。不得仅更新登记表而留下错误的常量偏置。匿名句柄只能用于其所属上下文，不能将旧句柄套到重新编译的原始线路。

固定匿名参数时，必须把值写入对应的实际数值槽，并真正关闭该槽的活动标记，再重建活动映射；不能只从输入列表删除一项。这里的匿名句柄指混合上下文中的 `Parameter`。纯数值整数 map 的旧配置保持不变，本轮不新增按整数 ID 使用 `fixed` 的接口。

原始数值线路的 `reset_parameters!` 和 activate/deactivate 保留原有数值槽及别名语义。含未绑定命名表达式的模板继续通过绑定或 `fixed` 修改，不把旧原地槽向量重新解释为独立变量向量。

## 统一映射与梯度

上述例子中，记第一个门的匿名参数为 a，输入为 `[a, θ]`，三个活动门槽为：

```text
α = [a, θ, 2θ + 0.1]
A = [1 0; 0 1; 0 2]
b = [0, 0, 0.1]
```

数值匿名槽贡献单位行；命名表达式贡献现有仿射行。固定变量的贡献并入常数，固定槽退出活动行。保留 `length(map) == nparameters(compiled.template)`，独立输入数由 `nparameters(map)` 给出。

伴随梯度仍回传 `A' * gα`，参数移位仍按门的每次出现位置独立计算，再回传完整梯度和协方差。FD 和 SPSA 继续在完整独立输入空间中扰动。此次整合不增加新的梯度算法或后端能力。

Zygote 的两参数绑定规则必须捕获这一次前向编译得到的 map，不能在反向阶段重新编译并产生匿名身份，也不能重复乘两次映射。

结构上已经明确不支持的梯度路径仍应在绑定和执行前拒绝；依赖实际数值的检查继续延迟到真实绑定点。不能因为使用混合映射就跳过所有旧预检。

## 兼容范围

| 场景 | 处理 |
| --- | --- |
| 纯数值线路，无显式 map | 保留整数 `ParameterMap` 和旧槽顺序 |
| 纯数值线路，显式整数共享 map | 保留原共享语义 |
| 纯命名线路 | 保留当前仿射语义 |
| 命名加固定数值 | 保留当前行为 |
| 命名加数值活动槽 | 自动编译为统一仿射映射 |
| 混合线路附带旧整数 `parameter_map` | 明确拒绝，不将它暗中解释为“只管理匿名槽” |

混合线路需要共享时复用显式 `Parameter`。整数 map 与命名表达式的组合映射可另行设计，不阻塞三种声明的直接混用。

数值构造器仍返回原数值门。普通活动叶节点可以直接贡献单位映射行，并复用既有绑定 writer，避免将所有第三方指令强制塞入只接受 Gate 的符号包装。固定第三方部分槽仍以其公开活动掩码或 materialization 能力为限。

`Parameter` 本身继续只保存身份与名称，不保存当前训练值。匿名来源、初值和顺序资料属于编译上下文；后端仍接收数值指令。

## 实现与验收

实现集中在现有编译层，不改模拟内核：

1. 将 `_reject_anonymous_parameters` 替换为参数登记遍历，同时生成匿名句柄、来源和初值。
2. 扩展 `_affine_rows!`，为普通数值活动叶节点补单位行，补齐物理活动槽布局协议，并处理固定后的数值写入和活动槽裁剪。
3. 在 map 中保存初值和来源元信息，增加上下文查询、`initial_parameters` 及上下文复用重载。
4. Objective、ShotObjective、prepared execution/estimation、直接绑定和扫描统一复用该上下文，不各自生成另一套身份。
5. 保留旧整数路径和已有梯度实现，补齐前向 map 捕获及结构预检。

验收至少覆盖以下结果：

- 三种声明直接同线使用，绑定、前向、伴随、参数移位和 AD 与手工规范化参考一致。
- 编译、查询、初始化和失败绑定均不推进模拟 RNG；匿名初值始终等于构造时已有数值。
- 同门对象重复出现、相等初值、多参数门、嵌套和条件双分支均保留正确的独立输入及顺序。
- 更新匿名变量后，后续训练使用更新值；普通绑定不补回默认初值。
- 默认顺序、显式重排、命名共享及仿射系数产生正确梯度和非对角协方差。
- 固定命名或匿名变量、全固定、常量消项、初值缺失及整数共享初值冲突均有确定行为。
- 上下文复制和复用保留匿名身份；不同上下文句柄、源结构及活动布局改变后不允许误套旧 map。
- 旧数值绑定、raw reset 别名、整数共享、异常拒绝顺序、外部指令和可选扩展继续通过回归。

原始线路与 `noise_model` 一起传入 prepared 接口时，先展开固定噪声，再编译一次。已有编译上下文可继续配置读出误差；会改变指令布局的噪声展开明确拒绝，并提示从原始线路准备，避免旧匿名来源和新布局发生错配。
